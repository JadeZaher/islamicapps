# Machine translation candidates

`generate_machine_translation_candidates.py` creates append-only, review-only
English candidates for `translation:*` rows in a curation backlog. It supports
the existing local LM Studio transport and an explicitly selected OpenRouter
transport. Neither transport writes canonical data or
`translation_overrides.jsonl`, and every event remains `candidate_only` and
`machine_unreviewed`.

## Full-schema input is required

The checked-in canonical `all_hadiths_unified.csv.gz` has the legacy schema.
The generator can derive stable identity from that file only for exact Sunni K6
rows. It cannot safely bind Imami, Zaydi, Ibadi, or other full-schema rows, so a
cross-tradition run must use the isolated incomplete-curation master and backlog
generated by:

```powershell
python regen_unified_csvs.py --allow-incomplete-curation
```

Those artifacts are expected at:

- `development/incomplete-curation/all_hadiths_unified.incomplete.csv.gz`
- `development/incomplete-curation/curation_backlog.incomplete.csv`

The current full-schema backlog has 12,833 translation-eligible rows: 12,831
translation status/content failures plus two source-identity translation
collisions. The separate eight `source:missing_arabic` rows are not translation
inputs. Regenerate the incomplete artifacts and trust the command's dry-run
count over this dated documentation if the corpus changes.

## Pilot gate before a full run

Before approving a new model or prompt identity, first select 10-15 stable
record IDs covering multiple traditions, works, input lengths, and translation
issue types. The r7 identity completed this gate before its bounded candidate
run was authorized. R8 changes semantic steering, so its minimum targeted pilot
must cover all four affected contexts in a fresh artifact/checkpoint pair.
`--record-id` is repeatable, validates that every requested ID exists and has a
`translation:*` issue, and processes matches in deterministic backlog order. It
cannot be combined with `--limit`. Run the following from `datasets/hadith-data`:

```powershell
python generate_machine_translation_candidates.py `
  --backend openrouter --dry-run `
  --backlog development/incomplete-curation/curation_backlog.incomplete.csv `
  --master development/incomplete-curation/all_hadiths_unified.incomplete.csv.gz `
  --output machine_translation_candidates/openrouter_gemini_2_5_flash_v8_semantic_pilot_2026-07-22.jsonl `
  --checkpoint machine_translation_candidates/openrouter_gemini_2_5_flash_v8_semantic_pilot_2026-07-22.sqlite3 `
  --max-cost-usd 0.10 --max-retries 8 `
  --record-id 'k6:7471' `
  --record-id 'k6:12234' `
  --record-id 'k6:16093' `
  --record-id 'k6:16103'
```

The dry run reports both total and selected eligible counts and never loads an
API key. Run the same command without `--dry-run` only after verifying the exact
selection. The earlier 14-row r7 pilot covered missing English, Arabic leakage
in all four traditions, cross-tradition placeholders and same-as-Arabic
failures, both source-identity collisions, and the 55,003-character maximum
row. The four-row r8 delta pilot must prove the corrected agency, demographic,
legal-opposition, and race-result senses. A qualified reviewer must inspect the
pilot's complete isnad, matn,
names, terminology, ambiguity sidecars, and source binding before authorizing a
full run. A mechanically accepted pilot does not constitute that authorization.
Paid OpenRouter generation without exact `--record-id` flags is fail-closed;
only a later, explicit post-review run may add `--allow-full-run`.

`--exclude-record-id` is repeatable and validates every value against an exact
translation-eligible backlog row. Exclusions are applied before claims, so they
produce no candidate event, checkpoint row, or model spend. Their IDs and count
appear in dry-run output, and the sorted exclusion set is bound into the pipeline
identity. Keep this exclusion on every later scale run:
`thaqalayn:06840b21d9e61e1ab351aec4` is a Kitab al-Ghayba Introduction/paratext,
not a report to machine-translate as a hadith candidate.

`--start-after-record-id` provides a deterministic suffix for a fresh identity.
It validates one exact translation-eligible anchor, skips that row and every
eligible row before it, and cannot be combined with `--record-id` or exclusion
of the anchor. The anchor, its exact ordered eligible-prefix digest, and exact
pilot selection are bound into pipeline identity. To continue r8 after the
immutable r7 boundary, use a fresh r8 artifact/checkpoint with
`--allow-full-run --start-after-record-id 'k6:16257'`, excluding both
`thaqalayn:06840b21d9e61e1ab351aec4` and
`thaqalayn:2a1ca7a8bc366eadfcbcb80f` explicitly.

```powershell
python generate_machine_translation_candidates.py `
  --backend openrouter --allow-full-run `
  --backlog development/incomplete-curation/curation_backlog.incomplete.csv `
  --master development/incomplete-curation/all_hadiths_unified.incomplete.csv.gz `
  --output machine_translation_candidates/openrouter_gemini_2_5_flash_v8_suffix_2026-07-22.jsonl `
  --checkpoint machine_translation_candidates/openrouter_gemini_2_5_flash_v8_suffix_2026-07-22.sqlite3 `
  --max-cost-usd 10.65 --max-retries 8 `
  --start-after-record-id 'k6:16257' `
  --exclude-record-id 'thaqalayn:06840b21d9e61e1ab351aec4' `
  --exclude-record-id 'thaqalayn:2a1ca7a8bc366eadfcbcb80f'
```

Do not copy r7 checkpoint rows or relabel r7 JSONL events: review/promotion must
retain the separate r7 prefix and r8 suffix provenance.

### 2026-07-22 pilot outcome

The initial 14-row paid pilot produced thirteen mechanical accepts and correctly
rejected one non-text separator, but independent review found a silent internal
omission in a 30,498-character Al-Kafi translation. That result blocked the
queue and led to the segmented protections below. A later r6 stress pilot
confirmed the omitted passage was preserved; review then found duplicated
English across two distinct segments in the 55,003-character maximum row. The
r7 validator catches that defect offline. The bounded r7 candidate run was
authorized with that maximum row and confirmed paratext excluded for separate
handling, then paused after finalized row `k6:16257`. Review of the prefix found
four deterministic semantic hazards: permitting rendered as analysis, invented
running/speed in a horse passage, Mu'awiyah's observer role reversed, and young
unmarried women rendered as freed slaves. R8 adds full-reconstruction guards for
those contexts and requires the targeted pilot above. See
`OPENROUTER_PILOT_REPORT.md` and `../DATA_QUALITY_REPORT.md` for accounting and
review evidence.

The first segmented-v3 pilot exposed two structural contract issues rather than
translation failures: long hash-bearing IDs were not copied exactly for two
rows, and protected question/answer spans left the 55,003-character `ʿUyun` row
without a legal boundary. Revision r2 uses simple ordered IDs (`S0001`, `S0002`,
...) while retaining offsets and hashes client-side. Revision r3 adds a final
deterministic code-point boundary only when a mathematically safe 400–600 window
contains no whitespace. Its bumped artifact/prompt/policy identity requires a fresh
pilot artifact and checkpoint.

Revision r4 responds to the next pilot's two fail-closed rejections. The
55,003-character row returned only part of a 110-item structured array despite a
`stop` finish reason, so r4 uses 500–800-character segments targeting 700 and caps
one response at 80 items. The Al-Kafi warning rejection was a validator false
positive: one admonitory `إياكم` and one ordinary prayer pronoun were both
counted. R4 distinguishes those constructions and supplies an explicit per-segment
minimum anchor. Its identity was superseded by the provider-compatibility revision
below before full-queue authorization.

Revision r5 keeps the client-side 80-segment planning and validation cap but
removes JSON Schema `maxItems`. The provider rejected that schema keyword with
an excessive-serving-states HTTP 400 before inference. Exact returned count,
identity, duplication, and order remain client-enforced. Artifact version 7 and
prompt identity `hadith-machine-translation-v4-segmented-r5` require fresh paths.

Revision r6 recognizes one additional definite no-charge response shape: a
choice-level 429 whose prompt, completion, and total token counts and reported
cost are all exactly zero. It receives the same bounded retry treatment as HTTP
429. Exhausting either rate-limit form records a non-terminal row error so other
work can continue and `--retry-errors` can revisit it later. Artifact version 8
and prompt identity `hadith-machine-translation-v4-segmented-r6` require fresh
paths.

Revision r7 adds a final long-input duplication guard after a pilot response
reused the same 933-character English block for different Arabic segments. If
an exact English translation hash of at least 80 normalized characters appears
for two or more distinct source-segment hashes, the row and every involved
segment are rejected. Short recurring formulas and identical repeated source
segments remain allowed. Artifact version 9 and prompt identity
`hadith-machine-translation-v4-segmented-r7` require fresh paths.

Revision r8 strengthens grammatical-role, contextual-polysemy, and no-invented-
manner steering. Full reconstructed translations are checked for the four known
high-confidence contexts documented in the pilot outcome. Artifact version 10
and prompt identity `hadith-machine-translation-v4-segmented-r8` require fresh
paths; r7 prefix events remain under their original identity.

## OpenRouter backend

OpenRouter use is opt-in with `--backend openrouter`. Its primary default is
`google/gemini-2.5-flash`, selected as a cost-conscious high-quality translation
model; no model guarantees scholarly accuracy. The endpoint is hard-allowlisted
to exactly `https://openrouter.ai/api/v1`. Credentials load first from
`OPENROUTER_KEY`, then `OPENROUTER_API_KEY`, then the repository-root `.env`.
UTF-8, BOM-marked or null-pattern UTF-16, and safely matching quote wrappers are
supported. Keys and provider error bodies are never written to logs or events.

Requests remain one atomic, non-streaming paid response per canonical row. They
use prompt version `hadith-machine-translation-v4-segmented-r8`, which treats the
Arabic field as untrusted data,
requires complete isnad and matn preservation, and explicitly protects Imami
and Shi'a terminology from neutralization. OpenRouter must honor:

- a strict top-level `segments` array whose entries contain only `segment_id`,
  `translation`, `uncertain`, and `uncertainties`; the client plans at most 80
  entries, while the provider-facing schema omits `maxItems` for compatibility;
- reasoning effort `none`;
- `provider.require_parameters=true`;
- `provider.data_collection=deny`;
- `provider.allow_fallbacks=true`; and
- `stream=false`.

The client rejects API error objects, any finish reason other than `stop`, an
invalid or extra schema field, missing/duplicate/reordered/changed segment IDs,
model-declared uncertainty, a response model that does not exactly match the
requested model, and the normal mechanical translation failures. Model matching
is checked after reported cost is recorded.
Events preserve the raw validated structured fields and the response ID, actual
model, actual provider, finish reasons, token usage, and provider-reported cost.
If count, identity, duplication, or order validation fails, the rejection retains
only bounded sanitized returned/missing/extra/duplicate IDs and counts, never the
untrusted translations.
No authorization header or credential surface is retained.

Only a definite no-charge HTTP 429 or an audited zero-token, zero-cost embedded
choice-level 429 retries. Backoff is exponential and honors a bounded
`Retry-After`; the embedded form uses five seconds. Exhausting either form is a
non-terminal row error, allowing the worker to continue and a later explicit
`--retry-errors` run to revisit it. HTTP 5xx, timeout, network/transport ambiguity,
over-limit body, or unreadable response may already have incurred cost, so they
are never retried and permanently poison the shared spend audit until manual
checkpoint/artifact reconciliation. Authentication, payment, and request or
configuration failures stop after one audited error. Terminal and spend blocks
are rechecked transactionally before every claim, including by already-running
workers. After fixing a known terminal cause, an operator must explicitly use
`--retry-errors`; that flag cannot clear unauditable spend.

OpenRouter defaults to a separate artifact and checkpoint so the local LM
Studio history cannot be reused accidentally:

- `openrouter_gemini_2_5_flash_candidates.jsonl`
- `openrouter_gemini_2_5_flash_checkpoint.sqlite3`

Checkpoint metadata is bound to backend, endpoint, requested model, the actual
prompt hash, structured-schema hash, provider policy, and resolved output path.
A checkpoint is also bound to the exact exclusion set and segmentation policy.
A missing legacy identity on a checkpoint containing work or spend, or any
identity mismatch, fails closed and requires a new path.

### Long-report segmentation and coverage

The canonical hadith/report row is always the logical unit; segmentation never
creates new records or changes source identity. A source longer than 4,000
characters is deterministically represented inside its single request as
ordered, non-overlapping 500–800-character source segments targeting roughly
700 characters each. A request may contain at most 80 segments; the planner
rejects before dispatch when even 80 maximum-sized segments cannot cover the
source. Boundaries are chosen in this order: terminal Arabic
punctuation, the start of a recognized `فإن قال` question/answer discourse unit,
high-level `وإياكم` / `واعلموا` / `يا أيها` discourse markers, numbered chain
starts, then whitespace. The planner avoids a boundary immediately after `عن`,
`حدثنا`, `حدثني`, `أخبرنا`, `أخبرني`, or `قال`; if every otherwise-valid option
in a 500–800-character window follows one of those connectors, it uses the
nearest whitespace fallback. All segments remain adjacent in the same request,
so this fallback does not discard context. Only when no whitespace exists in the
mathematically safe window does the planner use a deterministic code-point
boundary; exact reconstruction and the 500–800-character bounds remain mandatory.

Model-visible segment IDs are deliberately simple ordered values such as
`S0001`; the response must return every exact ID once and in order. The client
audit plan separately binds each ID to its exact character span and source
SHA-256, and binds the complete plan hash to the row. Each segment is checked
independently for nonblank Latin-majority content and a conservative
Latin-to-Arabic letter ratio before translations are concatenated in source
order. Every segment carries `required_beware_count`, computed from
diacritic-insensitive high-confidence admonitory uses of `إياكم`. Strong
`و…`, `أن…`, and vocative constructions are counted; bare and `من…` forms need
an independent-clause guard. Ordinary object pronouns in prayers such as
`أجارنا الله وإياكم من…` are not warning anchors. The prompt requires at
least that many exact `Beware` tokens, and the client rejects a segment that
falls below the minimum; extra natural uses do not fail coverage. These are
coverage guards, not proof of semantic or scholarly accuracy.

After individual segment checks, the client also groups exact English hashes.
Reuse of at least 80 normalized characters across distinct Arabic segment hashes
adds `duplicate_translation_across_distinct_source_segments` to the row and all
involved segments. The source-hash distinction and length floor avoid rejecting
genuinely repeated source text or short conventional formulas.

Blank, ASCII-only, numeric, and punctuation/separator source values are rejected
before dispatch unless they contain an Arabic-script letter. This prevents the
known `s` and `* * * * *` backlog artifacts from consuming paid requests.

### Cost and size bounds

The general hard source ceiling is 65,536 characters. OpenRouter's 80-by-800
single-request capacity is 64,000 characters, so a larger source fails planning
before dispatch. Segmentation protects coverage but does not create multiple paid
requests: each row still gets one dynamic output
allowance based on total source length, with an absolute ceiling of 32,768
tokens. The complete HTTP body remains byte-bounded.

`--max-cost-usd` defaults to `$15` for OpenRouter. Every provider-reported
`usage.cost` is idempotently recorded in the shared SQLite checkpoint. The
ledger is checked transactionally before the next row is claimed. Multiple
workers may exceed the ceiling only by the cost of requests already in flight
when the shared total crosses the limit; therefore use one worker for a pilot
and choose a budget below the absolute account-level amount available. A
missing or invalid cost stops the run because spending can no longer be audited.
This is a client-side response ledger, not an account escrow: a provider charge
for a response lost to a timeout cannot be learned from that missing response.
Keep the ceiling conservative and monitor account billing during larger work.

## Local LM Studio backend

Local mode remains the default. From `datasets/hadith-data`, run an
OpenAI-compatible server on a loopback HTTP address and provide the exact local
build identifier:

```powershell
python generate_machine_translation_candidates.py --dry-run
python generate_machine_translation_candidates.py --backend local --limit 5 `
  --model google/gemma-4-e4b --model-version gguf:gemma4:Q4_K_M
```

Non-loopback local endpoints are rejected. Local responses remain streamed and
bounded by response bytes and event chunks. OpenRouter's output/checkpoint and
spend rules do not alter the local transport. The v3 local branch still requests
one plain English translation with no structured uncertainty fields and uses
`local_lmstudio_v2_candidates.jsonl` and
`local_lmstudio_v2_checkpoint.sqlite3` defaults, leaving the historical v1
pilot and checkpoint untouched.

## Artifact, checkpoint, and validation contract

Each JSONL event binds the exact stripped-Arabic SHA-256 to stable `record_id`,
source row identity, model and prompt identity, UTC time, generation settings,
candidate English, and validation result. Before a model request, the row must
resolve to the selected master by exact stable ID and Arabic hash; source record,
source label, tradition, provenance locator, and hadith number are cross-checked.
Full-schema rows require every one of those identity/provenance fields to be
nonblank. Missing or stale identities are skipped and make the invocation fail.

The SQLite checkpoint holds only resumability state, the disk-backed master
collision index, work leases, accepted-candidate collision data, pipeline
identity, and OpenRouter spend. Workers sharing a queue must share both output
and checkpoint. JSONL appends are file-locked, flushed, and synced before a
checkpoint advances. Re-running skips accepted and rejected rows by default;
use `--retry-rejected` only after an intentional input, prompt, or model change,
which generally also requires a new identity-bound checkpoint.

After identity validation and before any work claim, startup reconciles durable
state in both directions. For every record/hash history, JSONL event count must
equal checkpoint `attempts` and the last event status must equal the checkpoint
status. In OpenRouter mode, every non-empty artifact `model_response_id` must be
unique and the exact set must equal the spend-ledger response IDs. Missing,
extra, duplicated, malformed, or crash-torn state fails closed before dispatch;
the tool does not auto-repair it. Preserve the files and reconcile them manually
before resuming.

Checkpoint status is additionally scoped to a SHA-256 of each row's complete
canonical identity: record and upstream IDs, source, tradition, provenance,
hadith ID/number, and Arabic hash. Correcting any of those fields prevents an
older accepted or rejected status from silently skipping the corrected row.

`--output` must remain a `.jsonl` file under this directory. Corpus, manifest,
backlog, curation, override, checkpoint, and artifact-lock path collisions are
rejected.

Mechanical validation rejects blank/non-Arabic source, blank text, refusals,
placeholders, copied input, Arabic-script leakage, a non-Latin-majority result,
suspiciously short per-segment output, missing/reordered source coverage, warning
anchor mismatch, substantial exact English reused across distinct source
segments, and English reused for divergent Arabic under one source identity.
These checks
cannot establish faithful translation, edition identity, rights clearance, or
scholarly approval.

## Human review and promotion

1. Review every candidate against its hash-bound Arabic and authoritative work
   or edition. Verify complete isnad and matn, names, order, doctrinal terms,
   ambiguity, attribution, and rights.
2. After review, author a separate `translation_overrides.jsonl` entry with the
   exact identity/hash, reviewed English, specific provenance, model where
   applicable, and `human_verified` or `source_verified`. Never bulk-copy the
   candidate artifact.
3. Run the normal fail-closed regeneration. A nonblank candidate never clears a
   publication gate by itself.
