## 6. Exactly what must change to emit Postgres COPY-ready CSVs
Already COPY-compatible: UTF-8 no BOM, LF, `csv.writer(dialect="excel", QUOTE_MINIMAL)` (export_bundle.py:276-281). Quoted embedded newlines/quotes are valid for `COPY ... WITH (FORMAT csv, HEADER true, ENCODING 'UTF8')` (never text format). Booleans are true/false and ints plain digits: both fine.
NULL vs empty: every None becomes unquoted empty cell (`"" if value is None else str(value)`, export_bundle.py:240-243). COPY CSV default NULL = unquoted empty, so blanks load as NULL (fine for nullable FK/int; but real empty strings are indistinguishable). Decide: accept (recommended) or use an explicit NULL token.
Whitespace: hadith_no is unstripped (row 1 is " 1 ") and translation text keeps leading spaces/runs of spaces; trim at load or in exporter.
Change list:
1. Headers: emit `typed_column_name(h)` (contract.py:435 exists); drop `:LABEL`/`:TYPE`/`:START_ID`/`:END_ID`; drop the duplicate import_id/id pair (remove values.insert(1, values[0]) at export_bundle.py:233-236). Type tokens live only in contract.py NODE_FILES/RELATIONSHIP_FILES + `_rel()` (248-264); namespace regexes at 409-411. Writer is `_Stage.write_files` (266-306).
2. Replace relationship files with FK columns: the ~35 `stage.put("relationships/...")` call sites (export_bundle.py lines 771-1491) become extra columns on the owning node row. At hadith creation (line 1011) collection_id, tradition_node_id, source_id are already in scope; book/chapter ids come from `_structure_nodes` (392-513). Chain row already carries hadith_id; mention row already carries chain_id, add narrator_id from the resolved branch (resolves_to put at ~1425); translation row gets hadith_id from translation_of (1199).
3. Drop derivable edges (next_in_chain, includes, includes_mention, has_chain, narrated_from) or emit as derived/optional; keep their counts in the manifest as derived invariants.
4. Rework validate_bundle.py: it is keyed to Neo4j semantics (id_namespace/start_namespace/end_namespace helpers, `_relationship_id_columns` at 203, orphan-edge and :LABEL checks). Re-express as FK-existence, PK uniqueness, UNIQUE(chain_id, position) contiguity, adjacency = mentions - chains. Arabic hash round-trip, translation provenance, rawi binding, manifest integrity, determinism compare, candidate separation, curation binding and publication_blockers are Neo4j-independent and reusable.
5. Manifest/determinism: keep `deterministic_json_bytes` (contract.py:456; sort_keys, no timestamps), `sha256_file`, `graph_content_hash` (463-484; sorted {path, bytes, sha256, header, row_count}); sort-key ordering via SQLite `ORDER BY sort_key` (write_files) keeps bytes stable. Bump BUNDLE_SCHEMA_VERSION (2) / BUNDLE_VERSION (2026.07.23.2) in contract.py:11-12 and add `target: postgres`. Replace manifest `import` block and `_support_files` (516-636; emits neo4j-admin-import.ps1 + post_import_schema.cypher) with `schema.sql` (tables, constraints, indexes) and `load.sql` (ordered `\copy` / COPY FROM STDIN; server-side file COPY is unavailable on Railway).
6. RECOMMENDED lowest-risk path: leave export_bundle.py and validate_bundle.py untouched (proven 12-gate pipeline, isnad extraction not re-derived) and add `export_postgres.py`: stream a VALIDATED neo4j bundle (check manifest sha256s first) into SQLite, join relationship files into FK columns, write ~12 COPY CSVs plus its own manifest bound to the source bundle content_sha256. Estimated ~300-400 new lines vs rewriting 1,848 + 2,977 lines. Cost: two-stage build, 646 MB intermediate.
7. Additions the bundle lacks and PG needs: grade/assessment rows (unified CSV grade_* columns), matn_en/school/chain_type/narration_level, English for machine-candidate rows (Translation already supports candidate_only but exporter hard-omits), chain_indx from the legacy master to populate narrator_id, and an embeddings table (NOT produced here; key by hadith id + arabic_sha256 for invalidation).
